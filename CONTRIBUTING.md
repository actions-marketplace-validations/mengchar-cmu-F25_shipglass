# Contributing to Shipglass

Shipglass helps people understand the files inside their release archives. We welcome small improvements that make the comparison more accurate, the report easier to understand, or the first run simpler.

## Develop locally

Use Python 3.10 or newer:

```sh
git clone https://github.com/mengchar-cmu-F25/shipglass.git
cd shipglass
python -m pip install -e .
python -m unittest discover -s tests -v
python -m shipglass demo -o report.html
```

Open `report.html` in your browser to inspect report changes. The application has no third-party runtime dependencies.

## Report a problem

Include the command you ran, your Python version and operating system, what happened, and what you expected. A tiny synthetic archive is especially useful for parser bugs. Do not attach private release packages, credentials, or reports containing private paths.

If you found a security vulnerability, follow [SECURITY.md](SECURITY.md).

## Send a change

1. Keep the change focused on one problem. For larger changes, describe the use case in an issue first so we can agree on the scope.
2. Add a focused regression test when fixing behavior that is not already covered. Prefer synthetic fixtures generated by the test over checked-in binary archives.
3. Run the test suite. For report changes, generate the demo and check it in a browser at desktop and narrow widths.
4. Explain the resulting behavior, the relevant checks, and any remaining limitations in the pull request.

Commit messages should describe the change, for example `fix: handle empty ZIP archives` or `docs: clarify wheel comparisons`.

## Keep the scope small

- Preserve offline operation and the standard-library runtime.
- Treat archive names and metadata as untrusted input. Never execute archived content.
- Keep file contents out of generated reports.
- Label observations precisely: a filename caution is not proof of a secret or vulnerability.
- Introduce new archive formats or integrations with a concrete user example and tests for the format's edge cases.

See [the roadmap](docs/roadmap.md) for the current priorities.
